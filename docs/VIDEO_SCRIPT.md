# 演示视频脚本（6 分钟 · PPT + 实录混合版）

> **形式**：PPT 讲逻辑，实录片段证明真实可运行。比例约 4:6（PPT 4 段、实录 4 段）。
> **目标**：评审看完能回答三个问题——① 解决什么问题 ② 真的能跑吗 ③ 做得有多扎实。
> **总时长**：6:00–6:20（验收要求 3–8 分钟）。

---

## 一、总体设计

### 为什么用混合形式

| 纯 PPT | 纯录屏 | 混合（本方案） |
|---|---|---|
| 显得没做出来 | 看不出技术含量 | 逻辑清楚 + 真实可验 |
| 评委看不到产品 | 6 分钟都在等加载 | 每一秒都有信息 |

### 风格要求（与产品一致）

- 16:9，1920×1080，帧率 30
- 主色 `#1F5FD0`，背景纯白，正文深灰 `#1B2531`
- 字体：思源黑体 / 微软雅黑；标题 40–44pt，正文 24–28pt，注释 18pt
- **每页最多 3 个要点**，能用图的不用表，能用表的不用字
- 不用切换动画、不用飞入淡出、不用 emoji

### 严谨性红线

| 不要说 | 应该说 |
|---|---|
| "业界领先""完美解决" | "在 28 份模拟合同、75 条标注上，检出率 96%" |
| "100% 准确" | "原文定位准确率 100%（口径见测试报告）" |
| "所有风险都能发现" | "漏检 3 条，均为缺失型风险，已在报告中说明" |
| "依据充分" | "18 条已溯源至法规条文，其余标注为未检索到依据" |

**每个数字都要能落到 `docs/TEST_REPORT.md` 的具体章节**，评委若追问可直接翻到。

### 段 2｜问题与方案（0:22–1:00，38 秒）

**画面（PPT 第 2 页）** 左右对比两栏

```
现状                          方案
─────────────────────────────────────────────
合同 100 条以上               上传 → 自动切分条款
人工逐条比对规则              逐条比对 40 条规则
易漏、标准不统一              原文定位 + 三级分级
修改意见靠经验                给出可直接采纳的表述
```

**旁白**

> 贷款合同一般一百条上下，人工审查要逐条对照利率、担保、违约、合规四类要求。
> 漏检和标准不一是常态。
>
> 我们做的事是：把 40 条规则做成可检索的知识库，让智能体逐条比对，
> 输出带原文定位、风险等级和修改建议的结构化结果。
>
> 下面是实际操作。

---

### 段 3｜上传与审查（1:00–1:52，52 秒）

**实录**：从桌面拖入 `C03_制造业中型企业_抵押_5000万.docx`

**录制要点**

1. 拖入文件后**立刻**把鼠标移开，让状态条完整入镜
2. 状态条要拍到三行变化：`正在解析…` → `已解析 106 条条款（12032 字）…` → `审查完成：6 处提示，用时 41 秒`
3. 等待期间不要剪掉——正好配旁白
4. 结果出现后停 2 秒再继续

**旁白**

> 把合同拖进来就行。系统先解析文件、按「第X条」切分条款，
> 同时对每条建立索引。
>
> 这一步值得说明：**切分和字符偏移是代码做的，不是模型做的**。
> 因为定位必须精确到字符，交给模型就不可控了。
>
> 右边正在调用智能体。它挂载了 40 条规则的知识库，
> 要在逐条比对后输出结构化 JSON。
>
> 四十秒，六处提示。

---

### 段 4｜双栏联动（1:52–2:40，48 秒）

**实录**：点击右栏卡片 → 左栏滚动并高亮 → 再点左栏高亮文字 → 回到卡片

**录制要点**

1. 先点「高」筛选，展示 2 条高风险
2. 点第一条卡片，停顿 1.5 秒（让滚动完成）
3. 依次读出四个字段：原文 / 问题 / 建议 / 依据
4. **鼠标悬停在"建议"那段文字上**，让评委看清这是完整可替换的表述

**旁白**

> 每条风险讲四件事。
>
> 第一，原文是哪一句——左栏对应位置会高亮，反过来点原文也能跳回卡片。
>
> 第二，为什么是问题。这里指出的是罚息按三倍计收且排除上限，
> 超出部分可能不被法院支持，对出借人不利。
>
> 第三，应该怎么改。不是"建议完善"，而是可以直接替换的条款表述。
>
> 第四，依据——如果没有检索到权威条文，它会如实写「未检索到权威依据」，
> 而不是编一个法条。

---

### 段 5｜授信比对与导出（2:40–3:15，35 秒）

**实录**：滚动到「授信批复比对」→ 指出差异 → 点「⋯」导出 Word → 打开文件

**录制要点**

1. 比对表要拍全（要素 / 合同 / 授信批复 / 说明）
2. Word 打开后停留 2 秒，让标题和条目入镜
3. 不要剪辑打开文件的过程（证明文件真能用）

**旁白**

> 如果同时给了授信批复，系统会比对要素是否一致。
> 这里利率比批复高 15BP、担保方式与批复不同、批复要求的自有资金比例没有写进合同——三项都会提示。
>
> 结果可以导出 Word，带免责声明，可以直接归档。

---

### 段 6｜架构与三个关键设计（3:15–4:05，50 秒）

**画面（PPT 第 3 页）** 架构图

```
┌────────────┐   ┌──────────────┐   ┌─────────────┐
│ 前端        │→ │ FastAPI 服务  │→ │ Nexent 智能体│
│ 三栏联动    │   │ 解析/切分/导出│   │ 40 条规则    │
└────────────┘   └──────────────┘   └─────────────┘
                        ↓
                  data/ 条款·标注·结果
```

**画面（PPT 第 4 页）** 三个关键设计（每条一行 + 一句解释）

```
① 定位不交给模型     条款切分与偏移由代码计算，模型只判断是否违规
② 判定闸门写在提示词  知识库讲"什么算问题"，提示词讲"什么不算"
③ 规则两级分类       客观判据的 20 条计分，主观权衡的 20 条仅作提示
```

**旁白**

> 架构分三层：前端负责展示和联动，服务层负责解析、切分和导出，
> 智能体负责判断。
>
> 三个设计决定了结果质量。
>
> 一，定位不交给模型。模型只说"这条违规"，位置由代码算。
>
> 二，判定闸门写在提示词而不是知识库里。这一点来自实测：
> 把合规反例放进知识库，检索会因语义相似反而抬高该规则的触发权重，误报反而上升。
>
> 三，规则分两级。有客观判据的二十条计入指标，
> 需要主观权衡的二十条（比如"违约情形是否过宽"）只作提示，不参与评分。

---

### 段 7｜指标与验证方法（4:05–4:45，40 秒）

**画面（PPT 第 5 页）** 表格 + 右侧一小段"口径说明"

```
指标                 实测     要求      判定
────────────────────────────────────────────
风险条款检出率       96.0%    ≥85%     通过
误报率                6.5%    ≤15%     通过
原文定位准确率      100.0%   =100%     通过
风险等级一致率      100.0%    ≥85%     通过
修改建议可用性       94.4%    ≥85%     通过
三次一致性（Jaccard） 1.000   ≥0.90    通过
```

右下角小字：`样本：28 份合同 / 约 2900 条条款 / 75 条计分标注`

**旁白**

> 这是自测结果，样本是二十八份模拟合同、七十五条人工标注。
>
> 五项验收指标全部达标，同一份合同连续审查三次，
> 结果集合完全一致。
>
> 需要说明：这里的检出率并不是百分之百，有 3 条漏检，
> 都是"缺失型"风险——模型在原文里找不到对应文字时会选择不报。
> 这个取舍是有意的：我们优先保证报了的就是对的。

---

### 段 8｜误报率从 38% 到 6.5%（4:45–5:25，40 秒）

**画面（PPT 第 6 页）** 三行递进表

```
阶段                改动                            误报率
──────────────────────────────────────────────────────
初版                —                                38.0%
数据修复            合规表述改为写明具体金额           27.7%
提示词自证要求      输出前必须复述判定条件并引用原文    6.5%
```

**旁白**

> 这个数字不是一次做出来的。
>
> 复核 28 条误报后发现，其中 25 条不是凭空捏造，而是**规则套用错误**——
> 模型发现了别的问题，却挂到最接近的规则编号上。
>
> 比如把"意向书失效"归到"解除后清算顺序"，把"只有诉讼管辖"归到"诉讼与仲裁并存"。
>
> 所以补标注只能消掉 3 条。真正有效的是在提示词里加一条：
> **输出前必须复述规则的判定条件，并指出条款中的对应文字；做不到就删除该条。**
>
> 误报率因此降到 6.5%，检出率只从 97% 降到 96%。

> 法规依据逐条溯源，查不到的如实写"未检索到"。

## 六、被追问时的答辩要点（备用，不进视频）

| 可能的问题 | 回答 |
|---|---|
| 误报率怎么算的 | 匹配键 (条款, 风险类型)；FP/(FP+TP)，样本 75 条计分标注 |
| 为什么只有 20 条规则计分 | 另 20 条属主观权衡（如"情形是否过宽"），用它算误报率没有意义，已在测试报告说明 |
| 定位 100% 怎么保证 | 条款切分与字符偏移由代码计算；模型只输出 quote，服务端校验其必须是原文子串 |
| 数据集真实吗 | 全部自造，20+ 份合同、40 条规则全覆盖、11 组边界样本 |
| 法条依据可靠吗 | 18 条已溯源，其余标注"未检索到权威依据"，不编造 |
