## 四、数据构造的约束

| 约束 | 做法 |
|---|---|
| 规则全覆盖 | 40 条规则在**每一份**合同中都落入至少一个条款，避免「模型报对了却算误报」 |
| 标注可校验 | 每条标注须通过 `tools/validate_labels.py`：引用必须是原文子串、偏移切片必须等于引用 |
| 风险可定位 | 每条风险在合同中的位置唯一，不跨条款拼接 |
| 参数一致 | 金额、利率、期限在全文一致，避免自相矛盾导致误判 |
| 无真实信息 | 人名、企业名、地址均为虚构（如「示例市」「某某制造有限公司」） |

## 五、复现方式

```bash
python tools/check_coverage.py           # 校验 40 条规则覆盖情况
python tools/validate_labels.py          # 校验 147 条标注的引用与偏移
python tools/batch_run.py             # 批量推理
python tools/gate.py --data-root data    # 过确定性闸门
python tools/evaluate.py --data-root data --out docs/TEST_REPORT.md
```

## 六、向量知识库配置

| 配置项 | 取值 | 规模 / 参数 | 说明 |
|---|---|---|---|
| 知识库 | contract-rules | 1 份文档 | 挂载于 contract_review，单智能体专属 |
| 文档 | 
ules-full.md | 40 条 · 13,829 字符 · 34.4 KB | 四条信息：判定条件 / 合规定式 / 缺陷形态 / 已知误报 |
| 分块 | 13 个分块 | 每块约 1 KB | 按规则分节切分，检索粒度为「单条规则」 |
| 向量模型 | ge-m3 | 1024 维 | 部署在本地 Ollama，不依赖外部接口 |
| 检索方式 | 语义相似度 | Top-K 命中 | 命中后返回该规则的判定条件，供模型比对 |
| 合规定式 | **不入知识库** | 改写入提示词 | 实测入库会抬高误报，见下方结论 |
| 字段口径 | judge 字段 | 20 计分 + 20 提示 | 知识库与规则库一一对应，避免两处不一致 |

### 两个结论

| 结论 | 依据 |
|---|---|
| 按规则分节切分（13 块）而不是按字数均分 | 一次检索命中一条完整规则，不会跨规则拼接 |
| 合规定式不进知识库，改放提示词 | 实测误报 1 → 2 条：检索按语义相似排序，反例与问题条款用词雷同，抬高该规则触发权重 |
